## H1 — informe_jsonl_runs.txt: un artefacto generado vive versionado en la raíz

**Problema**: `informe_jsonl_runs.txt` (raíz del repo) es un informe
generado el 2026-10-05 ("Informe de archivos .jsonl en .runs") que quedó
versionado por fuera de la higiene de salidas/ (2026-10-05: "todas las
piezas escribían sus informes en la raíz... ahora el default de TODAS las
salidas es salidas/"). Ningún código lo referencia (verificado por grep).

**Fix**: moverlo a su casa y sacarlo del versionado, en UN comando:
`git mv informe_jsonl_runs.txt salidas/informe_jsonl_runs.txt`
(git mv deja staged el delete; el destino está en .gitignore vía salidas/,
así que queda como artefacto local, regenerable con `main.py informe`).
Correlo con run_command. No hay código que tocar ni test que agregar.

## H2 — supervisor.clave_de: la firma ignora su primer parámetro

**Problema** (`supervisor.py:78`):
```python
def clave_de(herramienta, args):
    """La firma canónica de una llamada: herramienta + args ordenados."""
    return json.dumps(args or {}, sort_keys=True, ensure_ascii=False)
```
El docstring promete "herramienta + args" pero la función IGNORA
`herramienta` (la herramienta ya viaja en la tupla `firma = (h, clave)` de
los call sites — el parámetro es mentira). Call sites: L272
(`clave_de(herramienta, args)`) y L298 (`clave_de(h, a)`), ambos en
supervisor.py; ningún test la referencia (verificado por grep).

**Fix**: `def clave_de(args):` con docstring honesto ("La firma canónica
de los args de una llamada: json con claves ordenadas — la herramienta la
aporta la tupla (herramienta, clave) de quien llama."), y los dos call
sites actualizados. Cero cambio de comportamiento (los tests del
supervisor — caché de idénticas, veto de repetidas — siguen verde tal
cual: son el candado).

## H3 — mcp_server: dos caminos silenciosos en el allowlist

**Problema** (`mcp_server.py`, loop de exposición):
1. Un nombre de MCP_EXPOSE sin implementación (`fn is None`) se salta con
   `continue` MUDO — un typo en el setting expone menos de lo pedido y
   nadie se entera.
2. Un nombre CON implementación pero SIN esquema en TOOLS recibe
   `descripciones.get(nombre, "")` — descripción vacía silenciosa (el
   cliente MCP ve una tool sin saber qué hace).

**Fix**: extraer la selección a una función PURA y audible:

```python
def elegir_exposicion(permitir, impls, descripciones):
    """(expuestas, aviso). Devuelve las tools a exponer y un aviso de
    nombres problemáticos del allowlist: sin implementación (typo en
    MCP_EXPOSE) o sin descripción en TOOLS. Degradación, no crash."""
    expuestas, faltantes, sin_desc = [], [], []
    for nombre in sorted(permitir):
        fn = impls.get(nombre)
        if fn is None:
            faltantes.append(nombre)
            continue
        if not descripciones.get(nombre):
            sin_desc.append(nombre)
        expuestas.append(nombre)
    aviso = None
    if faltantes or sin_desc:
        partes = []
        if faltantes:
            partes.append("sin implementación (¿typo en MCP_EXPOSE?): " + ", ".join(faltantes))
        if sin_desc:
            partes.append("sin descripción en TOOLS: " + ", ".join(sin_desc))
        aviso = "[mcp-server] allowlist con problemas — " + "; ".join(partes)
    return expuestas, aviso
```

`main()` la usa y el aviso va a **stderr** (regla del archivo: stdout es
el canal del protocolo MCP). El resto no cambia.

**Candado** (`tests/test_smoke.py`): función pura, sin fastmcp —
1. nombre desconocido → no expuesto + aviso lo menciona;
2. nombre con impl sin descripción → expuesto + aviso lo menciona;
3. caso normal → todo expuesto, aviso None.
