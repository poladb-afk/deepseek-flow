## La corrida que falla (por qué cuenta 0)

`catálogo` · `conteo-routing` · s3, US$0,0082, 8 llamadas, adopción OK
(`catalogo` → `usar` → supervisor corrió): el supervisor propuso
`run_command` con `awk`/`wc` sobre la ruta absoluta del archivo; el scope lo
rechazó (`fuera-de-scope`) y **no ejecutó**. El chat respondió: *"I cannot
report the number … no count was actually executed"*, ofreció paginar con
`read_file` y pidió autorización, pero no lo hizo. La verificación busca el
número (**1374**) en el reporte → 0.

El mismo caso, con el mismo scope, se resolvió en las otras corridas: base s1
pagina con `read_file` (ve "líneas 1–3 de 1374" y "1370–1374 de 1374"), base s3
y catálogo s1/s2 cuentan con `wc -l` (auto-lectura o dentro del supervisor) y
reportan **1374**. La base del mismo tema dio 3/3.

No es un error operativo: exit 0, sin timeout ni error de API, respuesta
completa y honesta. **No hay cláusula de re-corrida** en el spec y re-correr esa
celda porque falló sería post-hoc, así que cuenta 0. El fallo **no es de
descubrimiento del catálogo** (18/18 encontraron `run_supervisor` y lo
ejecutaron): es de recuperación del chat ante un comando rechazado, y decide el
veredicto porque el umbral pre-registrado era 18/18.
